# 配置说明

所有配置集中在 `app/config.py` 的 `Settings` 类，通过**环境变量或 `.env` 文件**注入。
字段名小写，环境变量名大写（`mysql_port` ↔ `MYSQL_PORT`），大小写不敏感。

- 配置样例：`.env.example`（复制为 `.env` 使用）
- 配置来源优先级：**真实环境变量 > `.env` 文件 > 代码默认值**
- 校验：Pydantic v2 强类型校验，取值非法时进程启动即报错（fail-fast）

> ⚠️ **Windows 路径必须用正斜杠**：`.env` 中写 `D:\modelscope\hub\models`
> 会被 dotenv 的转义规则吞掉一层，解析成 `D:\modelscope\hub`。
> 本项目已对路径做归一化容错（`model_cache_roots()`），但仍建议写 `D:/modelscope/hub/models`。

## 1. 服务与安全

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_NAME` | `parent-child-rag` | 应用名（日志与 FastAPI title 使用） |
| `DEBUG` | `false` | 调试模式；为 `true` 时日志级别降为 `DEBUG` |
| `CORS_ALLOW_ORIGINS` | `http://127.0.0.1,http://localhost` | CORS 来源白名单（逗号分隔）。**不使用 `*`**，且 `allow_credentials` 固定关闭 |
| `ADMIN_TOKEN` | 空 | `/api/v1/admin/*` 的访问令牌。留空 = 不校验（仅本机开发）；非空时需请求头 `X-Admin-Token` |
| `UPLOAD_MAX_MB` | `20` | 上传文件体积上限（MB）。超限返回 `413` |
| `UPLOAD_ALLOW_EXT` | `.md,.markdown,.txt,.pdf` | 上传扩展名白名单（逗号分隔）。不在名单内返回 `400` |
| `WARMUP_ON_STARTUP` | `true` | 启动时预热 BM25 词表 / 嵌入模型 / 重排模型 |

**`WARMUP_ON_STARTUP` 为什么默认开启**

嵌入模型与重排模型是**懒加载**的。若不预热，第一次 `/health` 或 `/search`／`/chat`
会同步等待模型加载（本机 BGE-M3 在 CPU 上约 6~10s，另加 jieba 词典加载），后果是：

1. 健康检查**超时**，K8s / 网关会误判服务不可用并反复重启；
2. 第一个真实用户请求要额外等待这段冷启动。

预热把这笔开销挪到启动阶段（启动总耗时约 8~10s），之后 `/health` 稳定在 **约 60ms**。
单个组件预热失败只记录日志、不阻断启动，并自动走降级路径
（嵌入 → `hash`，重排 → 空实现）。

> 上线前用 `/api/v1/health` 的 `detail.retrieval_ready` 判断是否预热成功：
> 正常应为 `true`；长期为 `false` 说明预热失败，查看服务端「预热 … 失败」日志。

**生产环境最小安全清单**

```bash
DEBUG=false
CORS_ALLOW_ORIGINS=https://your-domain.com
ADMIN_TOKEN=<强随机串>
# MySQL / Redis / Milvus 使用独立账号与强口令，不要沿用示例中的 123456
```

## 3. Redis（父文档内容缓存）

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `REDIS_HOST` / `REDIS_PORT` | `127.0.0.1` / `6379` | |
| `REDIS_DB` | `0` | |
| `REDIS_PASSWORD` | 空 | 生产建议开启 `requirepass` |
| `REDIS_PARENT_PREFIX` | `psd:parent:` | key 前缀，最终形如 `psd:parent:12` |

> 引入 TTL 后需同步配置 `maxmemory` 与 `maxmemory-policy allkeys-lru`，
> 否则内存打满会直接写入失败。

| --- | --- | --- |

## 5. 分块参数

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PARENT_CHUNK_SIZE` | `1200` | 父块目标字数，**决定送入模型的上下文粒度** |
| `PARENT_CHUNK_OVERLAP` | `120` | 父块重叠（10%），避免句子被切断 |
| `CHILD_CHUNK_SIZE` | `280` | 子块目标字数，**决定检索精度** |
| `CHILD_CHUNK_OVERLAP` | `60` | 子块重叠（约 21%），降低会减少向量总量 |
| `MAX_PARENT_CHARS` | `4000` | 单个父块写入 Prompt 时的截断长度，控制 token 成本 |

**调参建议**

| 语料特征 | 子块 | 父块 | 理由 |
| --- | --- | --- | --- |
| 通用长文（技术文档） | 280 | 1200 | 默认值，父子粒度比约 4:1 |
| 工业短句 + 表格 + 故障码 | 180 ~ 220 | 1600 ~ 1800 | 短句场景 280 会混入多条无关步骤，稀释向量 |
| 法条 / 合同条款 | 250 ~ 300 | 1500 | 单条条款较长，需保证条款完整 |

> 硬约束：子块**绝不跨越父块边界**；Markdown 表格与围栏代码块作为「原子块」保护，
> 不做标点级拆分（`ATOMIC_OVERFLOW_RATIO = 2.5`，超限时只按行边界切）。

## 6. 检索参数

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `RETRIEVE_TOP_K` | `20` | Milvus 召回的**子块**数。语料 > 10 万子块建议 30~50 并配 Rerank |
| `FINAL_TOP_K` | `4` | 去重后送入模型的**父块**数。4 个 × 1200 字 ≈ 7k tokens |
| `HYBRID_RANKER` | `rrf` | `rrf`（只看排名，无需归一化，安全默认）或 `weighted` |
| `DENSE_WEIGHT` | `0.7` | 仅 `HYBRID_RANKER=weighted` 时生效（稠密权重） |
| `SPARSE_WEIGHT` | `0.3` | 仅 `HYBRID_RANKER=weighted` 时生效（稀疏权重） |
| `SCORE_RATIO_THRESHOLD` | `0.2` | 父块相对低分过滤：低于「最高分 × 该比例」丢弃；`0` = 不过滤 |

**父子分块专属逻辑**（不可配置，见 `app/services/retriever.py`）：

- 父块分数 = `max(命中子块分数) × (1 + 0.15 × 额外命中数)`
  —— **必须用乘法**：RRF 融合分只有 `0.016~0.033` 量级，固定加法偏置会压过真实排序信号。
- `explain`（单分支对照检索）由**请求体**控制，默认 `false`；开启会额外发起 2 次
  Milvus 查询，检索延迟约翻倍。

## 8. 稠密向量 Embedding

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `EMBEDDING_PROVIDER` | `hash` | `hash`（离线占位）/ `local`（本地模型）/ `api`（外部服务） |
| `EMBEDDING_MODEL` | `BAAI/bge-m3` | 模型名或仓库 id |
| `EMBEDDING_DIM` | `1024` | 向量维度，**必须与模型输出一致**（BGE-M3 = 1024） |
| `LOCAL_MODEL_PATH` | 空 | 显式指定本地模型目录；留空则自动从 ModelScope 缓存解析 |
| `MODELSCOPE_CACHE` | `D:\modelscope\hub\models` | ModelScope 模型缓存根目录（**建议写正斜杠**） |
| `EMBEDDING_DEVICE` | `cpu` | `cpu` / `cuda`。8GB 显存建议留给 7B LLM |
| `EMBEDDING_FP16` | `false` | 仅 `device=cuda` 时生效，可把权重占用从 2.1GB 降到约 1.1GB |
| `EMBEDDING_BATCH_SIZE` | `16` | 批大小；CPU 保持 16，GPU(fp16) 可 32~64 |
| `EMBEDDING_QUERY_INSTRUCTION` | 空 | 查询指令前缀。**bge-m3 留空**；`bge-large-zh` 填「为这个句子生成表示以用于检索相关文章：」 |
| `EMBEDDING_API_BASE` / `EMBEDDING_API_KEY` | 空 | 仅 `EMBEDDING_PROVIDER=api` 时需要 |

**三者对比**

| Provider | 依赖 | 检索质量 | 适用场景 |
| --- | --- | --- | --- |
| `hash` | 无 | 低（仅保证链路跑通） | 无模型/无网络时验证架构 |
| `local` | torch + sentence-transformers + 本地模型 | 高 | **推荐**：数据不出机 |
| `api` | 网络 + API Key | 高 | 无本地算力时 |

> **切换 Embedding 模型的后果**：语义空间改变，**必须重灌数据**
> （`scripts/reset_data.py --yes --reset-ids --reset-vocab` → `scripts/ingest_samples.py`）。
> 若维度也变化，还需 `python scripts/init_db.py --recreate` 重建集合。

## 9. Rerank 精排（可选）

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `RERANK_ENABLED` | `false` | 开启后对召回的**子块**做 Cross-Encoder 重排 |
| `RERANK_MODEL` | `BAAI/bge-reranker-v2-m3` | 模型名 |
| `RERANK_MODEL_PATH` | 空 | 本地目录；留空则自动从 ModelScope 解析 |
| `RERANK_DEVICE` | `cpu` | 与 7B LLM 共用 8GB 显存会 OOM，默认 CPU |
| `RERANK_FP16` | `false` | 仅 `device=cuda` 时生效 |
| `RERANK_CANDIDATES` | `0` | 参与重排的候选子块数；`0` = 沿用 `RETRIEVE_TOP_K` |
| `RERANK_KEEP` | `10` | 重排后保留的子块数（随后仍按 `parent_id` 聚合） |

**为什么重排作用在子块而不是父块**：子块才是检索单元（280 字），cross-encoder
计算量随长度增长，280 字 vs 1200 字差 4 倍以上；且子块分数可在同一尺度比较，
便于保留「多子块命中」信号。重排分数经 sigmoid 归一化到 `0~1`，
以兼容下游的相对阈值过滤。

> 依赖缺失或模型加载失败时自动降级为 `NoopReranker`（保持原顺序），不阻断检索。

## 10. 大模型

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_PROVIDER` | `auto` | `auto` / `ollama` / `openai` / `mock` |
| `LLM_OLLAMA_BASE` | `http://127.0.0.1:11434/v1` | `provider=ollama` 时使用的地址 |
| `LLM_OLLAMA_MODEL` | `qwen2.5:7b` | `provider=ollama` 且 `LLM_MODEL` 仍为 `gpt-4o-mini` 时自动采用 |
| `LLM_API_BASE` | `https://api.openai.com/v1` | 远程 OpenAI 兼容服务地址 |
| `LLM_API_KEY` | 空 | 远程服务密钥；**本地 Ollama 无需填写** |
| `LLM_MODEL` | `gpt-4o-mini` | 模型名 |
| `LLM_TEMPERATURE` | `0.2` | 事实型问答建议 `0.1`（越低越稳定） |
| `LLM_MAX_TOKENS` | `1024` | 单次生成上限。RAG 答案通常 512~1024 足够 |
| `LLM_TIMEOUT` | `60` | 超时（秒）。本地 7B 首次调用含模型加载（实测约 5s），建议 ≥120 |

**`provider` 判定规则**

| 取值 | 行为 |
| --- | --- |
| `ollama` | 强制走 `LLM_OLLAMA_BASE`，无需 Key |
| `openai` | 强制走 `LLM_API_BASE`，**必须**有 `LLM_API_KEY` |
| `auto` | 有 Key → 走 `openai`；否则若 `LLM_API_BASE` 指向本机/内网（`127.0.0.1`、`localhost`、`0.0.0.0`、`::1`、`host.docker.internal`）→ 也走 `openai`；都不满足 → 降级为抽取式回答 |
| `mock` | 强制抽取式回答（用于测试） |

> 判定基于**实例自身的 `base_url` 与 key**，而不是全局配置，
> 避免「用本地地址构造的实例被误判为降级」。
> `GET /api/v1/health` 的 `detail.llm` 会返回实际接线方式，可直接核对。

**本地模型选择建议（8GB 显存）**

| 模型 | 特点 | 用途 |
| --- | --- | --- |
| `qwen2.5:7b` | 无 think token、支持工具调用、速度快 | **RAG 主链路** |
| `deepseek-r1:7b` | 长链推理强，但输出大量 `think` | 仅用于难例纯推理，不用于 RAG 答案生成 |

## 11. 配置速查：三个典型场景

### 11.1 本机开发（零依赖，最快跑通）

```bash
EMBEDDING_PROVIDER=hash
LLM_PROVIDER=mock          # 强制抽取式，不调用外部服务
ADMIN_TOKEN=
```

### 11.2 本机 + 本地模型（推荐，数据不出机）

```bash
EMBEDDING_PROVIDER=local
EMBEDDING_DEVICE=cpu
MODELSCOPE_CACHE=D:/modelscope/hub/models
LLM_PROVIDER=ollama
LLM_OLLAMA_MODEL=qwen2.5:7b
RERANK_ENABLED=false       # 确认显存有余量后再开
```

### 11.3 生产部署（含安全加固）

```bash
DEBUG=false
CORS_ALLOW_ORIGINS=https://your-domain.com
ADMIN_TOKEN=<强随机串>
UPLOAD_MAX_MB=10
MYSQL_PASSWORD=<强口令>
REDIS_PASSWORD=<强口令>
MILVUS_TOKEN=root:<强口令>
EMBEDDING_PROVIDER=local    # 或 api
LLM_PROVIDER=openai
LLM_API_KEY=<key>
```

## 12. 配置相关排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Fail connecting to server ... UNAUTHENTICATED` | Milvus 开启鉴权但未配置 token | 设置 `MILVUS_TOKEN=root:<密码>` |
| 模型在本地却报「未找到本地快照」 | `.env` 中路径用了反斜杠被 dotenv 吞掉 | 改用正斜杠（代码已做容错，仍建议规范书写） |
| 检索结果为空 | ① 未灌数据；② 换过 Embedding 维度未重建集合；③ BM25 词表与入库时不一致 | `./stats` 核对数量；必要时重置重灌 |
| 启用 Rerank 后启动变慢 | 首次加载 cross-encoder 模型 | 属预期；或在索引阶段关闭重排 |
| 明明配了本地模型却走「降级模式」 | `LLM_PROVIDER` 仍为 `openai` 且无 Key | 改为 `ollama` 或 `auto`；用 `/health` 核对 `detail.llm` |
| 上传 `.pdf` 报 400 | 扩展名不在白名单或文件是扫描件（无文本层） | 调整 `UPLOAD_ALLOW_EXT`；扫描件需先 OCR |
| 500 但响应体没细节 | 有意为之（防信息泄漏） | 查看服务端日志中的 traceback |
| 本地脚本/测试访问 `127.0.0.1` 返回 404，但浏览器/curl 正常 | **Windows 系统代理**（WinINET 注册表）把本机地址也路由到了代理（本机实测代理 `127.0.0.1:26561`） | 关闭系统代理；或调用方用「禁用代理」的 opener（本项目 `tests/test_api_http.py` 与 `scripts/check_local_models.py` 已内置） |
| 重启机器后容器全停、集成测试报 `MySQL 不可用` | Docker Desktop 未随系统自启 | 启动 Docker Desktop；执行 `docker compose up -d`（全部服务均配了 `restart: unless-stopped`，Docker 就绪后会自动拉起，一般无需手动干预） |
| 换用统一 compose 后数据"消失"、报 `Table 'par_sub_split.parent_document_t' doesn't exist` | compose 使用了**新的命名卷**（`par_sub_split_*`），旧容器/旧卷中的数据不会自动迁移 | 重新初始化并灌数据：`python scripts/init_db.py` → `python scripts/ingest_samples.py`。若确实需要迁移旧数据，应先用 `docker cp`/`mysqldump` 导出旧容器再导入新容器 |
